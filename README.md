# Ginkgo 美食地图

> 电子科技大学 **Ginkgo 烹饪社** · 成都觅食指南
> 一口一杯，按杯论英雄。不好吃就举牌子。

一个**单文件**的社团内部美食地图：25 家店的种子数据、五档「杯型」评分、腾讯地图打点、
写评价、照片压缩、收集表导入、排行榜、多标签页实时互通。

---

## 一、怎么打开

**直接双击 `index.html`** 就行，不需要装任何东西、不需要起服务器、不需要联网就能看数据。

- 想看到地图打点，需要**联网**（腾讯地图 SDK 走 CDN）。断网时会自动降级：地图区显示一张
  友好提示卡，**列表、搜索、筛选、打分、导入导出、排行榜全部照常可用**，不会白屏也不会弹错误框。
- 推荐浏览器：Chrome / Edge / Safari 近两年的版本。
- 手机上也可以：宽度 < 900px 时自动变成「地图在上、列表在下」，详情是全屏抽屉。

> 文件构成：`index.html` 是**唯一交付物**（CSS / JS / 封面图全部内联，体积约 200 KB）。
> `build/` 是源码分块与构建脚本，方便后续维护，可以整个删掉不影响使用。

## 二、杯型评分规则（重点）

### 四个维度

| 维度 | 看什么 |
| --- | --- |
| 味道 taste | 调味、火候、食材新鲜度 |
| 性价比 value | 同样的钱能吃到多少东西，学生党视角 |
| 服务 service | 出餐速度、阿姨手抖不抖、加汤加饭爽不爽快 |
| 环境 ambience | 座位、空调、油烟、卫生、能不能久坐 |

每项 **0–10 分，步进 0.5**。

### 算分方式

```
单条评价总分 overall = (味道 + 性价比 + 服务 + 环境) / 4     ← 内部保留 2 位小数
店铺综合分 score     = 所有评价 overall 的算术平均          ← 展示保留 1 位小数
分维度均分           = 该维度所有评价的算术平均
推荐率               = 推荐数 / 评价总数
```

### 杯型五档（用 `>=` 判断，从上往下第一个命中）

| 杯型 | 分数 | 颜色 | 一句话 |
| --- | --- | --- | --- |
| 全家桶 | `>= 8.6` | `#C0392B` 红 + 金边 | 神店，冲 |
| 超大杯 | `>= 7.4` | `#B5651D` 深琥珀 | 强推 |
| 大杯 | `>= 6.2` | `#C98A4B` 焦糖 | 值得一去 |
| 中杯 | `>= 5.0` | `#D8B98A` 奶咖 | 中规中矩 |
| 小杯 | `< 5.0` | `#8A94A6` 灰 | 踩雷预警 |
| 待评级 | 无评价 | `#B9B2A4` | 等你来评 |

**关键细节**：杯型判定用的是**未四舍五入的原始分数**。所以 8.599 是超大杯、8.600 才是全家桶，
不会出现「显示 8.6 但其实是 8.55 被四舍五入」的错档。

## 三、怎么加店 / 怎么写评价

### 加一家店

1. 首屏或列表上方点 **「添加餐厅」**。
2. **先搜店名**（最省事的一条路）：
   - 输入 `aq羊肉串`，腾讯地图上只有一家 → **自动选中**，店名、地址、坐标一次性填好，地图跟着跳过去；
   - 输入 `海吃牛鲜`，同名两家 → 弹出候选列表，每条都带地址，点一个才采用；
   - 输入 `建设路海吃牛鲜` → 关键词更精确，直接命中那一家；
   - **腾讯地图上没有这家店**（小摊、新店常见）→ 退化成地址解析：输入 `玉林四巷`，
     地图直接跳到那条路并提示"已定位到 XX 路，请确认位置"，再点「在地图上点选位置」精确到门口。
3. 剩下的分类、人均、标签按需补。
4. 坐标一般不用管了。真要手填，展开「手动填经纬度（一般用不到）」——**坐标系必须是 GCJ-02**。
5. 也可以点「在地图上点选位置」：弹层收起、地图进入十字准星 → 点一下落点，坐标自动回填
   并显示预览 pin（按 `Esc` 可取消）。
6. 保存后地图上立刻出现新的杯子 pin，卡片上会显示「距校区 x.x km」。

> 搜索走的是腾讯地图的 `Suggestion`（联想）→ `Search`（城市检索）→ `Geocoder`（地址解析）
> 三级降级，全部由 SDK 内部走官方代理，页面里不出现任何地图密钥。
> 地图没能加载时搜索会提示不可用，此时仍可手填地址 + 地图点选。

> 卡片上的「待定位，点此补坐标」是给**收集表自动建档**的店准备的：如果你在导入时勾选了
> 「自动创建为待评级店铺」，这些店的坐标会临时落在清水河校区，点一下就能去地图上补准。

### 写一条评价

1. 点卡片进详情 → **「写评价」**（或者首屏「写评价」按钮，再下拉选店）。
2. 拖四个滑杆。拖动时上方会实时显示：
   - 本条总分；
   - 这家店**现在的杯型**；
   - **加上这条之后的预测杯型**和预测综合分。
3. 选「推荐 / 不推荐」，填昵称（会记住到下次），写正文（**至少 5 个字**，最多 500）。
4. 照片最多 3 张，支持点击选择和**拖拽上传**。前端会自动压到**最长边 1280、JPEG 0.78**，
   如果单张仍 > 600KB 就继续降质（0.68 → 0.58 → 0.48 → 0.38），然后存进浏览器 IndexedDB。
5. 提交后：写入 → 重算聚合 → 刷新地图 marker 与列表 → 提示「评价已记录，店铺杯型更新为 XX」。

**校验规则**：四项分数必须有效，正文 < 5 字会被就地拦下，不会发空评价。

## 四、怎么导数据

打开 **「数据管理」**（右上角或首屏「导入 / 导出」）。

### 1. JSON 全量快照

- **导出**：下载一个 `ginkgo-foodmap-YYYYMMDD-HHmm.json`，含全部店铺与评价。
  图片**只导出索引 key**，不含二进制 —— 照片永远只存在这台电脑的浏览器里。
- **导入**：按 `id` 去重，冲突以 `updatedAt` 更新的一方为准。可以拿来做「增量合并」，
  也可以用来在两台电脑之间搬数据（照片会丢，其余都在）。

### 2. 收集表 / CSV 导入（最常用）

支持三种输入：

1. 把表格内容**直接粘贴**进文本框（TSV / CSV 都行，Excel、腾讯文档、石墨复制出来都能用）；
2. 上传 `.csv` / `.tsv` / `.txt` 文件；
3. 点「下载导入模板 CSV」拿一份带 BOM 的模板（Excel 打开不乱码）。

内置了一个**轻量 CSV 解析器**，能正确处理：逗号/制表符/分号分隔、英文双引号包裹、
引号内的逗号和换行、`""` 转义、CRLF/LF/CR、UTF-8 BOM。

**表头自动识别**（中英文都认）：

| 字段 | 可用的表头写法 |
| --- | --- |
| 店名 | `店名` `餐厅` `店铺` `名称` `name` `restaurant` |
| 味道 | `味道` `口味` `taste` |
| 性价比 | `性价比` `价格` `value` `price` |
| 服务 | `服务` `service` |
| 环境 | `环境` `氛围` `ambience` `env` |
| 推荐 | `推荐` `是否推荐` `verdict` `recommend`（认 推荐/不推荐、是/否、yes/no、1/0） |
| 昵称 | `昵称` `姓名` `作者` `author` |
| 点评 | `点评` `内容` `评价` `text` `comment` |
| 日期 | `日期` `时间` `date` |

**导入流程**：解析 → 预览前 5 行 + 汇总「可导入 N 条 / 跳过 M 条（原因）」→ 勾选是否
「店名不存在时自动创建为待评级店铺」（默认勾选）→ 确认导入。

**跳过规则**：缺店名、某个分数有值但不在 0–10、正文少于 5 字 —— 这三种会跳过并给出原因。
分数留空的按 **7 分**补齐，并在提示里标出来。分数写法兼容 `8`、`8.5`、`8分`、`7/10`（取分子）。

**重复导入是安全的**：同一个店 + 同一个昵称 + 同一段正文会被判定为重复而跳过。

### 3. 怎么跟《腾讯文档 · 收集表》对接

1. 在腾讯文档里新建一个**收集表**，按这 9 题建字段（顺序随意，表头文字对得上即可）：

   | 收集表字段 | 题型 | 说明 |
   | --- | --- | --- |
   | 店名 | 填空题（必填） | 与地图里的店名保持一致；对不上会自动建档 |
   | 味道 | 数字 0–10 | 留空按 7 分补齐 |
   | 性价比 | 数字 0–10 | 同上 |
   | 服务 | 数字 0–10 | 同上 |
   | 环境 | 数字 0–10 | 同上 |
   | 推荐 | 单选：推荐 / 不推荐 | |
   | 昵称 | 填空题 | 留空显示「匿名社员」 |
   | 点评 | 多行文本 | 至少 5 个字 |
   | 日期 | 日期 | 可留空，默认导入时间 |

2. 收齐以后，在收集表右上角「…」→ **导出为 CSV**（或「下载数据」）。
3. 回到本页「数据管理」→「选择 .csv / .tsv / .txt 文件」（或直接打开 CSV 复制粘贴）→
   **解析并预览** → 看一眼「可导入 / 跳过」的数字 → **确认导入**。

## 五、怎么让大家看到同一份评价

### 先说结论：为什么不能直接读腾讯文档

浏览器里打不开腾讯文档的表格数据，原因有三个，绕不过去：

1. 腾讯文档的分享页需要登录态，接口要 OAuth 授权，**不会**把一个可匿名访问的 CSV/JSON 地址暴露出来；
2. 即使拿到页面地址，跨域（CORS）也会被浏览器拦掉；
3. 没有「只读、公开、可直接 fetch」的导出端点。

所以腾讯文档只能当**收集入口**（发收集表→导出 CSV→导入），做不到「别人一提交，你这边就变」。
真正要实时，必须有一个能被浏览器直接读写的共享存储。下面这条路线**免费**，不用租服务器。

### 三条路线，按需要选

| 方案 | 实时性 | 成本 | 适合 |
| --- | --- | --- | --- |
| **A. 云同步（推荐）** | 15 秒轮询，自动 | 0 元（Supabase 免费版） | 社团日常共用一份数据 |
| B. 收集表 CSV 导入 | 手动，导一次变一次 | 0 元，零注册 | 只想先收一波评价、不想注册任何账号 |
| C. 纯本地 | 无（仅自己这台电脑） | 0 元 | 单人写稿、演示 |

A 和 B 可以同时用：平时开着云同步，收集表导出的 CSV 也能随时灌进来合并。

### 方案 A：5 分钟接通云端（不用改代码）

打开应用 → 右上角「数据管理」→ 找到「云同步」区块：

1. 去 [supabase.com](https://supabase.com) 注册（免费，不用信用卡），新建一个 Project，
   等它从 "Setting up" 变成 **Active**（约 1–2 分钟；没变绿之前域名是解析不到的）。
2. Project Settings → API，复制两个值：
   - **Project URL**：形如 `https://abcdefghijklmno.supabase.co`（不是密钥！）
   - **API Key**：新版是 `sb_publishable_...`，老版是 `eyJ...` 开头的 anon JWT
3. 点面板里的「复制建表 SQL」→ 到 Supabase 左侧 **SQL Editor** 粘贴执行一次；
   回来把两个值填进去 → 点「保存并连接」。

> 地址栏对常见手滑做了兜底：漏 `https://` 会自动补，漏 `/rest/v1` 会自动补，结尾多余的斜杠会归一化；
> 但如果把**密钥**粘进地址栏，会直接报错「这串是密钥，不是地址」，不会静默失败。
>
> 新版 `sb_publishable_` 密钥只放在 `apikey` 头里；老版 `eyJ...` 的 anon JWT 才会同时带
> `Authorization: Bearer`。两者都支持，不用你手动区分。

**连不上时的排查顺序**

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 「这串是密钥，不是地址」 | 把 key 粘进了地址栏 | 地址是 `https://xxx.supabase.co`，不是 key |
| 「连不上服务器」 | 域名写错 / 项目还在初始化 / 已暂停 | 去后台看项目状态是否 **Active**，重启它 |
| 「连上了，但表还没建」 | 没跑建表 SQL | 复制 SQL 到 SQL Editor 执行一次 |
| 「密钥不对，或权限策略没建好」 | key 粘错，或 RLS 没建 | 重新复制 key；确认 SQL 里 `create policy` 都执行成功 |

连上之后：状态条变成「✓ 已同步到云端」，面板里能看到上次同步时间和待上传条数。
配置存在浏览器 localStorage（键 `ginkgo.sync.v1`），刷新不丢；换台电脑要重新填一次。

### 后端表结构

`restaurants`（店铺目录）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | 店铺 id |
| `name` | text | 店名 |
| `category` | text | 分类 |
| `price_level` | int | 1–4 人均档 |
| `address` | text | 地址 |
| `lat` / `lng` | float8 | GCJ-02 坐标 |
| `tags` | jsonb | 标签数组 |
| `closed` | bool | 是否停业 |
| `created_at` / `created_by` | timestamptz / text | 建档信息 |
| `needs_location` | bool | 收集表建档但未定位 |

`reviews`（评价）：`id` PK、`restaurant_id`、`author`、`scores`(jsonb)、`verdict`、`text`、`photos`(jsonb)、`created_at`、`updated_at`、`source`。

### 同步怎么工作（以及为什么必须先拉店铺）

- **先拉店铺，再拉评价**。如果只拉评价，别人新加的店在你本地不存在，
  这条评价会被当「孤儿」丢掉 —— 这正是之前「只看到默认评价」的根因。
- 首轮如果云端餐厅表是空的，会把本地 25 家店整体推上去，作为云端目录的起点。
- 评价按 `updated_at` 增量拉取，冲突一律**以更新时间新者为准**。
- 图片以 dataURL 存在 `photos` 字段里，单条评价的图片总量超过 700KB 就只传文字，
  避免请求体过大导致整条推送失败。
- 离线时不发请求，改动留在 `meta.pendingSync` / `meta.pendingRestaurants`，联网后自动补传。
- 任何失败都不阻塞界面：状态条转琥珀色，下次轮询静默重试。

> 安全提醒：`anon` key 是公开可写的前端密钥，任何拿到它的人都能往这两张表写数据。
> 社团内部用没问题；要防恶意写入，得在 Supabase 里加更严的 RLS 策略或接 Edge Function。

### 状态条含义

- `✓ 已同步到云端 · 16:42` —— 已连云端且最近一次成功；
- `✓ 已保存到本机 · 16:42` —— 本地模式；
- `离线模式，改动已暂存，联网后自动合并`（琥珀色）；
- `云端同步失败，已回退本地`（琥珀色）—— 本地功能不受影响。

## 六、数据与存储

- 主数据：`localStorage['ginkgo.foodmap.v1']`，结构见下：

```js
{
  version: 1,
  restaurants: [{ id, name, category, priceLevel, address, lng, lat, tags,
                  closed, source, needsLocation, createdAt, createdBy }],
  reviews: [{ id, restaurantId, author, scores: { taste, value, service, ambience },
              verdict, text, photos: [key], createdAt, updatedAt, source }],
  meta: { lastSyncAt, pendingSync: [], nickname, clearedAt }
}
```

- `meta.clearedAt` 记录「用户最后一次主动清空」的时间。清空后刷新**不会**再把示例数据塞回来
  （空态就是空态）；点「恢复示例数据」会把该字段清掉，示例数据才会重新载入。
- `id` 只允许 `A-Z a-z 0-9 _ -`（1–64 位）。不合规的 id 在归一化阶段**重新生成**
  （店铺 id 变了时会同步改写它下面评价的 `restaurantId`，不会产生孤儿评价），并且会把清洗后的结果
  直接写回本机 —— 外部导入的 JSON 既没法通过 id 注入 HTML，也没法把脏 id 留在存储里。

- 照片：`IndexedDB['ginkgo-foodmap-photos']` 的 `photos` 仓，key 就是 `reviews[].photos` 里的字符串。
- **脏数据不会让页面崩**：所有读取都走 `try/catch` + 字段级归一化（缺坐标补校区坐标、分数越界的评价
  整条丢弃、指向不存在店铺的评价丢弃）。JSON 解析失败会提示并回退到示例数据，且**不会立刻覆盖**
  你原来那坨数据，仍然可以手动导出抢救。

   注意浏览器端做不到，必须有服务端代理。
3. **评价互动**：点赞、举报、按「最有用」排序、回复。
4. **用户体系**：昵称 → 真正的账号，配合权限控制（谁能改别人的店）。
5. **路线规划**：把选中的几家店丢给腾讯地图的驾车/步行路线接口，生成「一条吃街」。
6. **图片转对象存储**：现在图片以 dataURL 存在评价行里，够社团用；量大了应该换 Supabase Storage，
   数据库只存 URL。
7. **数据可视化**：按区域/分类的热力分布、人均 vs 评分散点图。
8. **PWA**：加 manifest + service worker 做离线缓存，手机桌面直接打开。
9. **小程序版**：同一套数据模型可以平移到微信小程序（用腾讯位置服务）。

## 九、已知限制

- **多人共享要么接云端、要么导 CSV**。默认仍是本地模式（打开即用、零配置）；要让所有人看到
  同一份数据，按第五节接通 Supabase 免费版，或走收集表导入。浏览器无法直接读腾讯文档。
- **照片跨设备有条件**：云端模式下图片随评价一起同步（以 dataURL 存在 `photos` 字段），
  但单条评价图片总量超过 700KB 时会自动只传文字。纯本地模式下照片只在 IndexedDB 里。
- **云端密钥是公开可写的**：`anon` key 泄露等于谁都能写，社团内部用没问题，别公开到外网。
- **删除不同步**：本地删店/删评价只影响自己，云端记录会保留（下次拉取会回来）。
- **地图必须联网**：腾讯地图 GL JS 从 CDN 加载，离线时自动降级为提示卡，其余功能不受影响。
- **定位精度**：`navigator.geolocation` 返回 WGS84，页面里用内置的 WGS84→GCJ-02 偏移算法转换，
  城区误差通常在几十米内；拒绝授权会回退到全城视野。
- **种子数据是测评快照**，营业状态和价格随时可能变，出门前请再确认一下。
- 单文件体积约 200 KB（封面图已压成 640px 宽、JPEG q82，约 14 KB）。
