# 旧系统迁移计划

## 原则

旧目录 `ginkgo-food-map` 在迁移完成前保持不变。V2 不直接读取或覆盖旧系统运行时数据。

## 阶段

1. 建立工程、模块边界和数据库基础设施。
2. 设计用户、餐厅、评价和回复的数据模型。
3. 实现注册登录、JWT 或会话认证和 RBAC 权限。
4. 迁移餐厅查询与管理功能。
5. 迁移评价、评分聚合和回复功能。
6. 实现旧 `store.json` 到 MySQL 的一次性导入工具。
7. 将旧页面按业务能力逐步迁移到 Vue 模块，并完成端到端测试。
8. 灰度上线，旧系统切为只读，验证后下线。

## 第一阶段不做

- 不把旧版 `app.js` 复制到 V2；需要对照时只查看独立的原项目目录。
- 不继续使用 JSON 文件作为正式数据库。
- 不引入 Nacos、消息队列或多个 Spring Boot 进程；Redis 只承担缓存和会话等轻量职责。
- 不在没有身份模型之前迁移写入接口。
